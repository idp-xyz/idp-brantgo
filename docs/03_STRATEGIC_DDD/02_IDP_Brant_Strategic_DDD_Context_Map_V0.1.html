01

STRATEGIC DDD

战略结论与阅读方式

结论一

18 个候选上下文，4 个核心域

核价（CST）、报价与订单（TRD）、采购与供需分配（PUR）、业务结算（STL）规则密集，决定利润与履约承诺，是 Brant 的差异化所在。

结论二

报价、客户确认与订单合为 TRD

三者共享报价根冲突键、统一锁序与同事务资格重查；拆开会让 full_v1 转换名额与“占用后禁止替代”无法在一个事务内成立。

结论三

AI 能力层不是上下文，业务任务是

与 Cargo 一致，AI 网关、策略与回执放 internal/ai；BusinessTask 对人工与 AI 都成立，作为 TSK 上下文。

结论四

一致性策略先于代码

Python 依赖单库单事务串行化重查上游资格；Go 基线禁止跨上下文事务内读取，ADR-BR-004 必须先裁决。

阅读建议：产品与架构负责人先读第 01、03、07、12 章；领域工程师重点读第 04—06、08、10 章；实施负责人读第 11—13 章。

子域分层与投入策略

分类决定投入方式：核心域使用完整战术模式与强测试；支撑域在存在生命周期或法律约束处建聚合，其余用轻量应用服务；通用能力优先复用平台组件。分类不是永久标签，例如 SUP 是否升级为核心域取决于寻源比选能否形成竞争优势。

子域上下文为什么可检验标准
核心域 CoreCST TRD PUR STL核价、报价与订单、采购组织、业务结算决定外贸企业的利润与履约承诺，规则密集且是 Brant 的差异化所在。毛利与审批不可绕过；同根唯一订单；采购草稿与承诺分离；核销守恒。
增强支撑 Supporting+SUP供应条件被核价与采购共同消费，MOQ、阶梯、交期与费用口径直接影响成本正确性；是否升级为核心取决于寻源比选能否形成竞争优势。MOQ 分组、阶梯模式与费用包含关系可执行且有反例。
支撑域 SupportingPTY CAT POL INQ QLT FUL CLM CNX TSK业务必需、行业共性较强；在存在生命周期或法律约束处建聚合，其余用轻量应用服务。边界清晰、标准化接口、已核实版本可被下游精确引用。
条件支撑 ConditionalMFG STK仅在客户选择供料、在制或本仓路线时启用；启用即须交付其强制依赖。未启用时明确返回不支持，不以字段预留宣称能力。
通用能力 GenericEVD来源证据与文件存证没有外贸独有规则，可优先复用平台组件。内容不可变、访问按引用对象再鉴权。
可选包 OptionalCRM销售过程管理，关闭后核心交易与 Q01 仍成立。BC-AT24：CRM 关闭时整链可运行。
非上下文能力—身份（IAM／OIDC）、AI 能力层（internal/ai）、外部参考代码（internal/reference）、共享值对象（internal/kernel）、技术基础（internal/foundation）。不拥有业务事实；不被计入限界上下文。

Brant 的业务核心设计与 Python 实现要求：报价正式化、订单激活与成本冻结时，在同一事务内重查成本快照可采纳资格、已消费配置效力、审核人当前资格与供应条件效力；上游撤销先提交则新动作必须拒绝。Cargo 仓库结构基线规定每个上下文独立事务 owner（T1），对其他上下文的同步调用只允许在本上下文事务之外查询（T3）；idp-bento-go 在另一 owner 的事务中开事务返回 transactionConflict。

方案做法能否保持“反证先提交则拒绝”代价与风险
A 事务外预取＋事件风险暂停下游在事务前查询上游资格，提交时记录观察到的资格版本；上游撤销发布事件，下游消费后对已提交对象登记风险暂停否，变为事后检测，存在提交窗口完全符合 Cargo T1／T3；需要业务负责人接受规则放宽
B 受治理的资格守卫读取上游发布版本化的 SECURITY DEFINER 守卫函数（最小字段，函数内 FOR SHARE）；下游在自身事务内以自身 executor 调用，上游撤销以 FOR UPDATE 修改守卫行，由 PostgreSQL 行锁裁决先后是对 Cargo T3 与 DB2 的受控例外；守卫函数须登记、只读、版本化。运行时耦合：两个上下文永久同库；上游撤销须等待持有守卫的下游事务提交；上游守卫表的 DDL 会阻塞下游；每个命令对公司授权守卫行加 FOR SHARE，须压测热点行与撤权等待
C 合并相关上下文把 CST 的可采纳资格与 POL 已消费配置的效力并入 TRD 的事务 owner是上下文边界失真，核价与政策 Owner 失去自主；后续拆分成本高
决定（模拟评审接受，E0）

采用方案 B 实现资格守卫，同时采用方案 A 的事件传播处理已提交对象的风险登记；M0-10 已在 PostgreSQL 16 上完成 SC-04 竞争实测。适用范围按合同成立区分：quote.activate、quote.replace、cost_snapshot.freeze 发生在对外承诺之前，需要“反证先提交则拒绝”；order.activate 发生在合同成立之后，上游变化只需登记为由订单审批确认的风险（ADR-BR-013），可评估改用方案 A。事后风险登记依赖 ADR-BR-015 的死信与重放。由首席架构师、研发负责人与 TRD、CST 负责人签核对 Cargo 基线 T3 的例外。
