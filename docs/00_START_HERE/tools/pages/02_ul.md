## 01 适用范围与权威关系 {#s1}

统一语言不是全系统必须共用的一本大字典。它要求在一个限界上下文内部，代码、接口、事件、日志与页面始终用同一个词指同一个概念；跨上下文出现同一个词时，必须登记冲突并说明转换方式。

| 来源 | 本稿如何使用 |
|---|---|
| 产品与研发范围基线 V1.0 | 主体模型（3.1）、事实归属（3.2、3.5）、台账与核销（4.2）、AI 任务（8.5、16.1）、中国出口对象（22.1）、专业术语表（13.5） |
| 业务核心详细设计 V0.2 | 核心对象（4）、字段字典（5）、生命周期（6）、审核与转单（8）、对象控制与锁序（9） |
| 候选契约 | brant.trade-core、brant.foundation、brant.costing、brant.quotation 的对象与错误语义 |
| Python V0.50 | 表名、命令名与错误码，用于确认词条已被实现并追溯到测试 |
| Context Map V0.1 | 每个词条只归属一个上下文；跨上下文引用使用拥有方的已发布语言 |

> [!decision] 与 IDP-Cargo 的差异
> Cargo 的 UL 没有独立的询价对象，询价从 RATE 的报价草稿开始；Brant 保留 CustomerRFQ，因为询价是 AI 意图接收与人工核实的入口（SD-01）。Cargo 的 AI 术语属于平台而非业务上下文，Brant 沿用这一点；但 BusinessTask 与驱动方式无关，单列为 TSK 上下文（SD-08）。

## 05 语言不变量 {#s5}

语言不变量是词条定义中最容易被实现弄错、必须由测试证伪的规则。战术模型中的 {{=invariantRegister}} 条聚合不变量凡涉及语言规则的都引用这里的编号；纯技术或计算类不变量不另设语言编号。

## 09 词条治理与签核 {#s9}

- 新增或修改词条必须同时更新 JSON 事实源、受影响的上下文与契约，并说明迁移窗口；不得无痕更名。
- 弃用词条加 DEPRECATED- 前缀并保留历史引用，不删除。
- 批准按词条逐项记录（词条 ID、批准人、日期、证据），不能只调整整个文件的版本号。
- Python 中已经存在的名称（如 master、foundation）只用于追溯；Go 代码使用本表的上下文术语。
- 跨上下文冲突由首席架构师组织裁决，结果登记到语义决定表并同步 Context Map。
