## 01 工作坊方法与重建说明 {#s1}

事件风暴从真实凭证串起时间线：先写过去时的领域事件，再定位发起命令的角色与前置条件，然后放置策略、超时与反例，最后标出边界与未知。本稿缺少真实凭证，因此按以下方法重建：

| 步骤 | 本稿使用的材料 | 产出 |
|---|---|---|
| 收集业务凭证 | BRC-001 合成询价、两家供应报价、成本与付款计划 | 主链事实清单 |
| 描述发生过的事件 | Python V0.50 的 Outbox 事件名与状态迁移（quote.frozen、quote.activated 等） | 过去时事件 |
| 定位命令与角色 | 业务核心设计第 2 章角色表、Python 命令权限 | 命令、执行者与人工专属约束 |
| 放置策略与超时 | 详细设计第 6—9 章 | 策略与时效守卫 |
| 注入反例与并发 | BC-AT01—28、T03／T04 专项测试中的失败用例 | 7 个反例场景 |
| 标出边界与未知 | Context Map 候选上下文 | 热点与待裁决项 |

> [!warn] 不得把重建模型当作客户事实
> 合成样例只能证明规则在自己的假设下自洽。真实客户的岗位分工、单据形态、回复方式与异常频率必须在 G0 工作坊中取证，并回写本模型与 UL。

## 04 策略与自动化边界 {#s4}

策略描述“当某事实发生时，可以或必须做什么”。在 Brant 中，几乎所有策略都只开放下一步的可能性，而不自动执行生效动作；自动执行只发生在已授权的 BusinessTask 内，并且走与人工相同的命令路径。
