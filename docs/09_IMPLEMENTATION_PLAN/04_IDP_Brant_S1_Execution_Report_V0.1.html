结论摘要

G1 · C04、C05、C06

远程 CI 跑通

G1 · C09

受保护主干：负责人决定不配置

GitHub 免费版的私有仓库不提供分支保护与规则集（API 返回 403）；2026-11-11 仓库公开后可以配置，待负责人决定。负责人 2026-11-10 决定不升级、不配置；C09 本为非阻断项，记为接受的缺口，合并前以 PR 上的 CI 检查为准。

S1 公共骨架

命令账本

契约、权限、已存幂等结果、CAS 与状态、引用的准入顺序沿用 Python；业务变化、动作结果、审计与 Outbox 同一事务提交；重放重查当前权限与可见性；拒绝一律审计。

S1-01

EVD 来源四层身份与业务文件

内容按 SHA-256 在公司内去重；邮件按渠道、账户与消息 ID 识别，同消息不同正文拒绝；来源不可变；猜正文探测不到他人私有来源。业务文件最多 10 MiB，校验类型与文件头，版本链不分叉。

S1-02 · 03

PTY 主体与联系人、CAT 的 SKU

整稿草稿、人工核实、修订回到草稿并保留已核实版本、停用；主体用角色集合，同一主体可同时是客户与供应商；SKU 每次核实固定一个规格修订号。

S1-05 · 08

INQ 客户询价

draft／ready／cancelled／closed；确认只限人工，须覆盖全部来源；记录确认时客户、联系人行版本与每行 SKU 规格修订号。BRC-001 前段四行 120 PCS 确认为 ready，直接调用与经 HTTP 各重放一次。

S1-06 · C10

HTTP 入口、OIDC 与 OpenAPI 候选

1 MiB、64 层、10 万个值（名单导入另为 32 MiB、100 万个值）；拒绝重复键、null、浮点数、未知字段、大小写不同的键名与空字符串；访问令牌须有签发者、受众、有效期、租户、公司与显式的操作者类型。OpenAPI 3.1 候选由传输层的命令表与请求结构生成，测试保证与代码一致。

S1-04

POL 全部 18 种配置与 ConfigGuard v1

配置的修订、发布须由编制人以外的人工执行（数据库约束同样强制）、原子替代、退役；汇率按方向与用途、不推导反向、过期即阻断；税额拆分精确、未知可抵扣性阻断；单位换算按 SKU 规格修订、需舍入即拒绝；银行账号无敏感权限只见末四位；单据编号按公司、类型、年度原子分配；基础快照须有公司档案与定价政策。守卫函数对确切修订行 FOR SHARE，三种提交顺序实测符合设计。

S1-09 · S1-11

主体筛查与筛查名单

名单版本由合规岗位受控导入（来源、发布日期、文件 SHA-256、条目数），条目不可改；按 screening_regulation 启用的名单精确匹配；疑似命中由合规人工裁决，AI 与 system 不能裁决；正向名单绑定主体修订与条目内容，负向名单永久阻断；新名单版本或主体修订使结论不再通过。PartyScreeningGuard v1 在四种提交顺序下实测符合设计（TD-AT15）。

BC-D02 · C10

岗位模板与职责分离

15 个默认岗位由 05 阶段源文件生成，覆盖全部命令；禁止组合在定义与分配岗位时拒绝；专属权限（合规结论、名单导入、信用决定）只归其岗位。

S1-02 · S1-03

交易档案、地址与服务方角色、货号映射

地址随主体草稿核实并按修订保留；服务方角色由人工按可读证据核实，起讫地以 UN/LOCODE 表示；交易档案固定主体修订、付款与贸易条款和联系人版本，发布须由编制人以外的人工执行；货号映射按主体、角色与外部货号唯一发布（BUSINESS_KEY_CONFLICT），引用已核实的 SKU 规格修订，规格修订后旧引用为 REFERENCE_STALE。

S1-07

brant-cli 基础演示

foundation-demo 在新的合成公司里由独立的编制人与审核人发布 18 种配置 20 条，取得基础快照，经 POL 查询得出 854.81 CNY、含税 113.00 与 24 PCS，与 Python 一致；不调用模型。

C07

Inbox 去重与提交结果未知

消费方在一个事务内按事件 ID 去重并处理，重复投递只处理一次；丢失 COMMIT 应答报告为 COMMIT_UNCERTAIN，Reconcile 只读判定已提交、载荷冲突或未提交；在 PostgreSQL 16 上以注入故障的连接实测丢失 COMMIT 与丢失应答两种情形。

S1-10 · C13

Outbox 死信、告警与重放

四条放弃路径（含 Bento 在领取次数超限时的静默放弃）都写入死信并告警；撤销、否认与风险类事件为关键告警；人工按事件 ID 以原事件 ID 重放。
