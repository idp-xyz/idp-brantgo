S3 EXECUTION REPORT

结论摘要

S3-01 · S3-08

QuoteRoot 与对象控制

草稿整稿保存、修订与丢弃（人工或 AI），冻结限人工。冻结封存规范化的商业文档，business_hash 与 Python V0.50 protocol.py 逐字节一致：hash-vectors.json 的 4 个向量（含中文、换行、é 的两种形式与辅助平面排序）原样复现，TRD 自有向量经 Python protocol.py 核对。数据库校验哈希、拒绝修改封存修订，每根至多一个 active 修订。冻结先锁本根、再锁权限守卫，按上下文代码顺序调用 CAT、CST、INQ、POL、PTY 的守卫。对象控制在根行上，bind、stop、release 推进 control_epoch，每次写入与重放都经围栏；标签与内部备注不入哈希（BC-AT09）。

S3-02

服务端计算

纯函数包 calc：成本范围绑定（完整询价行、换算后数量、贸易与付款条款、地点与交付）、销售条款（税额适用、销售费用、重复义务拒绝）、行金额按币种 HALF_UP 舍入后求和、净销售经报价用汇率一次换算到比较币种、毛利精确比较 R − C ≥ R × minimum_margin 并给出精确差额、付款计划最大余数法。冻结只经服务端计算封存结果；INQ RfqRef v1 增加客户与联系人。T03 §5.3 合成案例、BC-AT04、06、07 与独立大整数算术对照（舍入与税额拆分 3000 例、汇率 2000 例、毛利与差额 5000 例、付款分配 3000 例）。

R13 · R14

PTY 与 CAT 守卫

TradingProfileGuard v1、AddressRoleGuard v1 与 SkuGuard v1 为 SECURITY DEFINER 函数，对引用的确切行及其可变的主体、联系人、SKU 行 FOR SHARE，结论与对应查询逐字段一致。三种提交顺序在 PostgreSQL 16 上实测：上游先提交则下游拒绝，下游先持锁则上游等待，上游先持锁则守卫等待后看到变化；去掉 FOR SHARE 后，依赖锁的顺序测试只在受影响的行失败。

S3-03 · S3-14

审核、批准与毛利例外

提交审核（frozen → pending_approval）、裁决（批准、退回、驳回）与撤销批准均限人工。审核人独立于编制人、冻结人与提交人，其当前授权在裁决事务内重读；批准绑定修订、哈希、目标、规则版本与期限。毛利低于最低值时普通批准不放行，须由持毛利例外权限、独立于编制人的人工在裁决中复述定价政策、最低毛利与精确差额（SC-02、BC-AT06）。放行时重查批准、期限、审核人资格与例外。

S3-04

正式文档与激活

渲染器 quote-text/0.1.0 复现 Python 的 candidate-document.txt 与 Python 渲染器生成的向量。取号前先试运行全部准入；编号由 POL number.issue 在事务前分配，事务失败只留空号，重试取回同一编号。激活在一个事务内锁根、重查放行与全部上游守卫、渲染，写入文档字节与绑定、提交证据、修订状态、动作结果、审计与 QuoteActivated；文档每次读取都按绑定校验字节（BC-AT22）。两个首次激活只有一个成功（TRD-INV-001）；编号、渲染与存储失败无残留（TRD-INV-016）。

S3-05

替代、撤回、取消、风险暂停与转换名额

替代在同一事务内使旧 active 修订 superseded；撤回结束 frozen 或待批修订并取消未决审核；取消结束 active 修订；历史均保留。撤销正式化所用的批准即登记风险暂停，修订不再服务新业务，不提供解除。转换名额 full_v1 在根上，被占后替代与取消为 ROOT_CONVERSION_LOCKED，替代与转换并发只有一个成功（SC-03、TRD-INV-010）。QuoteRevisionGuard v1 与修订查询供下游在事务内外使用。

S3-06 · S3-13

客户回复、Acceptance 与合同成立

回复绑定 active、未暂停正式修订的哈希、编号与期限，只增不改。只有 full_unconditional 的回复经人工核实、复述修订、哈希、客户、联系人与完整行集合后形成 Acceptance（BC-AT10、11）。合同成立按到达时间：到达早于 expires_at 即成立，核实晚于到期也成立（SC-07，PostgreSQL 上以激活后 8 秒到期的报价实测）；迟到为 ACCEPTANCE_LATE，不创建任何内容（TD-AT03、BC-AT12）。效力账本 valid → invalidated 或 disputed，disputed 可再作废，不回到 valid。AcceptanceGuard v1 供订单在事务内判定。

S3-07 · S3-13

销售订单、订单审批与风险确认

order.prepare 把已成立合同所确认的 active 正式修订转为草稿订单，同一事务占用转换名额；订单快照逐字复制封存的商业文档与 Acceptance，其 SHA-256 即订单哈希。订单审批由独立于准备人与请求人的人工给出，期限与报价无关，并逐项确认合同成立后的上游风险。order.activate 在一个事务内重查 Acceptance、修订、名额、正式文档、正式化批准与订单批准，未确认的上游变化为 ORDER_RISK_UNACKNOWLEDGED，主体筛查不为 clear 即拒绝；报价到期后按时成立的合同仍可生效（BC-AT13、SC-07）。已成立合同的修订不能被替代或取消（ACCEPTANCE_ALREADY_EXISTS）。ActiveOrderRef v1 与 OrderGuard v1 供 PUR 使用（R19）。

S3-09

quote_ready、历史、发送前准入与动作对账

quote_ready 判定修订现在能否服务下一步：对象控制、提交证据、文档字节、风险暂停、期限、批准与批准人当前资格、上游守卫、在当前输入上重新绑定的成本范围与销售条款、销售汇率时效。修订、审批、正式文档、提交证据与 Outbox 历史按报价根分页且不含载荷，Outbox 显示真实投递状态。发送前准入与发送目标只报告本地链条，没有发送渠道。同键重放与对账在事务前经 EVD 重查所引来源，读取、重放与对账都重查当前权限与数据范围（X-INV-003）。

S3-10 · S3-16

PUR 采购草稿、需求分配与作废

采购草稿从生效订单行与当前有效的供应条件准备，准备一次即不可变；一个订单行可按数量拆分给多个草稿与供应商，并发分配只有一个成功（TD-AT05、TD-AT06）；作废释放分配并保留记录。准备在事务内依次调用 CAT、CST、POL、PTY（新的 PartyGuard v1）、SUP 与 TRD OrderGuard 守卫；核价对照只记录不阻断（R21）。BRC-001 的 600.00 USD 草稿来自 960.00 USD 的生效订单。

S3-15

生效订单变更与结束；S/C 与 PI 渲染

变更经准备、提交（七个领域的影响评估）、独立裁决与应用，形成带哈希链的新订单修订；已出运的数量、SKU 与价格不被覆盖（TD-AT01）；OrderGuard v1 对旧修订的绑定答 REFERENCE_STALE。生效订单可取消、短交关闭或关闭，FUL、PUR、STK、STL 事实记为 not_wired，不视为通过。order-text/0.1.0 渲染外销合同与形式发票，以黄金文件固定。

S3-15

外销合同与形式发票

order.document.generate 以 POL 版式与 order-text/0.1.0 生成订单当前修订的 S/C 或 PI，POL 取号，绑定、字节与提交证据同一事务写入；订单修订推进后旧单据为 ORDER_DOCUMENT_STALE（TRD-INV-020）。law 区块打印来源报价封存的法律条款，变更后不变。order.document.record_signed 以 EVD 文件登记签署件与会签件，未签署的生成件不能冒充签署件。SIM-02 第 6 步（生效前生成 PI 并登记会签件）在 PostgreSQL 16 上运行。
