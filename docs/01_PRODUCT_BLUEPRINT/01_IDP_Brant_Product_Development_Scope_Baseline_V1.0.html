DEVELOPMENT BASELINE

产品定位、目标客户与业务边界

1.1 产品定位

IDP Brant 是 AI-Native Trade Operations Platform（AI 原生外贸业务运营平台）。面向中国境内 B2B 出口企业，管理从询价、寻源、核价报价、订单，到采购及生产协同、质量、出口履约、业务结算和经营分析的业务关系。AI承担资料理解和受控任务协作，业务服务维护权威事实、金额计算、权限和状态约束。

1.2 首发目标与客户验证

V1.0以中国境内单一经营主体、自营一般贸易货物出口作为首发范围基准；服装作为首个行业配置方向。该选择用于组织研发与验收，不表示已经取得真实客户需求、付费或上线证据。人数、营业额、订单量、售价和效率提升比例均不在缺乏实测时给出承诺。

1.3 业务全景与经营方式

业务全景覆盖需求、寻源与样品开发、报价订单、供给组织、生产／委外协同、质量、包装出运、业务结算及售后。寻源、样品和客户确认允许多轮往返；预收预付可先于履约。供应方式、作业层级、材料责任和交付路线分别建模，不以一条线性流程限制合法业务时序。

1.4 客户证据要求

在进入真实试点前，至少取得一笔普通出口及一笔变更／异常业务的脱敏资料，核对岗位、资料、实际系统、重复录入、等待和差异处理。探索性访谈可从3—5家经营方式可比较的企业开始；样本用于早期决策，不代表统计性市场验证。需求、客户原始证据、公开产品机制和设计假设分别登记。

1.5 首发范围与客户配置的关系

产品能力目录见第2章；首发中国业务配置见第21章；P0、B0与R1阶段见第14章。客户配置只能在已发布能力与规则范围内选择模板、责任人及允许的阈值；扩大经营模式、交易责任或专业处理方法属于范围变更。

2.4 模块与行业边界

2.5 共享基础能力与既有范围映射

DEVELOPMENT BASELINE

数量、结算台账与利润规则

4.1 精度与快照

全部关键计算采用十进制；参考计算使用 34 位有效数字。数量输入最多 6 位小数，单位价格最多 8 位，汇率最多 12 位，比例最多 8 位；超出约定精度拒绝或要求用户明确修订，不静默截断。

结算金额按币种配置的小数位数舍入；首批案例 CNY、USD 为 2 位，采用 HALF_UP。中间计算不按显示位数提前舍入；最终报价行金额、费用分配和核销按各自约定时点处理。数据库精度、数量及金额上界在技术 ADR 中绑定业务范围后冻结，并增加溢出边界测试。

订单、报价、采购、费用、结算及出运保存价格、币种、汇率、单位、模板和规则版本。主数据后续修改不重写历史；纠错使用调整和新版本。

4.2 业务台账及形成时点

台账或记录 形成依据 撤销或调整
订单承诺 生效订单及批准变更 变更、取消未执行部分或短交关闭
库存流水 已确认收货、出库、退货或盘点调整 通过相反方向的受控调整，保留来源
业务应收 销售结算单确认；默认来源为已确认出运明细 贷项、冲销或经审批调整
业务应付 采购结算单确认；来源为收货或直发交付证据及供应商依据 退货、借项或经审批调整
实际收付款 经核实的资金记录及凭据 新增退款或资金冲销记录
核销关系 将可用收付余额分配给应收应付 撤销核销产生新记录，不抹除资金事实

应收应付是本产品业务结算台账，不等同于法定总账。销售结算单是内部受控对象，与外贸商业发票、税务发票分别关联，不能互相替代。

预付款计划只管理合同节点和催收；实际货前收款登记为未核销预收余额，货后根据结算单核销。货前尾款也按同一规则登记，不需要虚构发货。若客户需要首期默认以外的账款形成政策，必须在范围评审中明确，不能私自改变系统规则。

同一出运或收货明细的已结算数量不能被重复结算。结算单冲销、实际退货与价格贷项分别处理：冲销按批准规则恢复可结算来源，退货贷项不能让同一已退商品的原发货再次被计费，纯价格贷项不改写实际数量。金额型费用单据按来源及分配关系防重。未来支持里程碑结算时，使用独立政策和来源标识，避免与货物结算重复形成业务应收。

4.3 数量与核销不变量

  • 生效订单的可发数量由订单数量、批准变更、已确认发货和短交关闭共同决定，默认不允许超发。
  • 同一库存成本层的可用数量扣除有效占用；确认出库采用并发安全的数量条件。
  • 核销金额不能超过来源资金的可用余额，也不能超过目标未结余额。
  • 首期按单据同币种核销；跨币种核销属于后续可选能力，未经过专项规则评审和验证不得启用。
  • 所有核销、撤销核销、贷项和退款均有来源与独立 ID。
  • 对已发生业务使用调整；重复请求与不同幂等键的业务重复，均需要唯一来源和约束检查。

4.4 库存与采购成本

首期候选采用可追溯采购批次的指定业务成本：收货形成数量及成本层，发货引用具体层；直发直接关联采购与出运分配，不虚构本企业仓库收发；实际存在我方外厂材料、在制品或受支持在途存货时，仍按相应归属及库存政策记账。该策略用于业务追溯，不宣称替代企业财务存货计价政策。

采购成本尚未最终确认时，成本层标记为 provisional；账单或费用确认后产生可追溯调整，并重算受影响的经营视图。已输出历史报表保留其“截至时间、成本版本及结算状态”，不能把实时重算冒充历史快照。

允许原批次来源明确的退货；无法确定原成本层的期初、混批或退货先进入待处理，不能猜测成本完成过账。通用可替代库存估值方法是否纳入首发，应由客户样例决定。

4.5 费用分配与经营口径

费用必须标明来源、受益订单或出运、费用类别、币种、换算依据及状态。按金额、数量或重量分配时，权重必须有数据依据、全部非负且合计大于零；无法取得有效权重时进入待处理。

非负费用按币种最小单位采用最大余数法：先计算精确份额，向下取得最小单位，再按余数从大到小分配余量；余数相同按稳定业务行 ID 排序。负向费用调整先对绝对值分配再恢复符号。禁止为了平账让最后一行吸收超额舍入并形成负分配。

净销售额按所用业务范围分别计算：预测采用生效订单的折扣后商品额及明确计入销售的收费；已确认口径采用已确认销售结算净额减有效贷项。明确标识的税额、代收代付与不计入销售项目分别保存，不混入默认经营口径。采购成本和订单直接费用只能归集一次，企业期间费用不默认分配到该指标。因此这里的“经营毛利”是已定义的内部管理指标，不能直接等同于法定财务报表项目。

8.6 上下文、记忆与数据新鲜度

上下文按以下来源区分：

  1. 权威业务事实：当前订单、库存、成本、账款、规则及版本。
  2. 经确认的业务资料：授权用户确认的条款、样衣及客户技术文件。
  3. 外部材料：来信、附件、网站内容及尚未确认的客户要求。
  4. 派生内容：模型摘要、候选匹配、方案和未执行建议。

保留恢复任务所必需的结构化步骤、工具输入输出引用、理由摘要和结果证据；不要求获取或保存模型内部隐藏推理。敏感原文、凭据及完整客户资料不应复制到普通运行日志。

规范化规则以 canonical.trade.v1 发布：字段白名单、Unicode NFC、固定字段名和币种大小写、十进制标准表示；只有明确声明为无序集合的字段才按稳定 ID 排序。保留规范化字节及算法版本；历史请求不得按新算法静默重算。SHA-256 仅标识一致内容，不代替权限或来源可信性。

报价状态采用 draft、pending_approval、active、superseded、expired、cancelled。effective_status 结合不可变修订、撤销／替代事件及核验时钟计算，不能因为定时任务延迟仍把过期报价视为有效。active 修订的内容修改必须建立新修订；正式替代需明确通知、审批和旧修订的后续处理，不假定创建草稿就自动撤销已发报价。
